01 — About

Useful software starts with a clear model.

Most of my work lives where relational databases meet full-stack applications — the point where a schema decision quietly determines how an interface will feel a year from now. I care about getting that model right before writing the screens on top of it.

That means thinking in schema design and normalized tables before REST APIs, and building on the MERN stack with SQL underneath rather than around it. I've paired that with CI/CD pipelines in Jenkins and Docker, and used Power BI to turn the same structured data into decisions non-engineers can act on.

I'm drawn to data-driven applications — software that doesn't just display information but is shaped by it.
